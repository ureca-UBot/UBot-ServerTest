# 실제 로컬 vLLM 1,500건 동시 부하 결과

실행일: 2026-10-22 · 판정: **PASS** · 서버 커밋: `e43e15b`

1,500건을 **18ms 범위**에 전송했고, 마지막 최종 상태 기록까지 **273.09초(4분 33.09초)**가 걸렸다. 금지어 300·임계값 미달 300·공식 FAQ 캐시 450·실제 LLM 답변 450건으로 목표 분포와 모두 일치했다. 접수/처리 오류·타임아웃·미완료·중복은 0건이다.

금지어 시간은 POST의 차단 응답 수신까지다. 나머지 전체 시간은 각 POST 시작부터 서버 DB의 `finished_at`까지이며 인증·접수·워커 대기를 포함한다. 완료 응답이 브라우저에 도착하는 시간과 UI 렌더링은 포함하지 않는다. 처리 시간은 `started_at → finished_at`으로 실제 임베딩·FAQ 검색·판정·생성·저장을 포함한다. 폴링 간격으로 늘어난 관측 시간은 위 수치에 사용하지 않았다. PostgreSQL의 `percentile_disc`로 LLM 처리·서버 전체 p50/p95를 독립 교차 확인했다.

LLM 답변의 대기 시간은 p50 **134.48초**, p95 **254.20초**였다. 캐시 처리 자체의 p95는 **53.09ms**지만 같은 워커 대기열을 거치므로 전체 p95가 **263.32초**까지 늘었다. 현재 조건에서는 워커 대기가 전체 응답 시간을 지배한다.

실제 모델 호출은 채팅 답변 450회·유사도 미달 후 판정 300회였다. 기존 미응답 묶음 이름 생성 스케줄러가 별도로 2회 호출되어 `kind=answer` 지표 차이는 452회다. 두 호출은 채팅 성공 450건에 포함하지 않았다. 모델 HTTP 재시도 횟수를 별도로 계측하지 않아 내부 전송 시도 횟수와의 동일성은 주장하지 않는다.

- GPU: NVIDIA GeForce RTX 3060, 12288 MiB; Docker: 16 CPUs, 25159159808 bytes memory; Java 21.0.11, heap 512m initial / 2g max.
- 실제 채팅 모델: `RedHatAI/Qwen3-4B-Instruct-2507-quantized.w4a16`, served name `ubot-chat`, max length 4096, GPU memory utilization 0.6. 실제 임베딩: BGE-M3(`ubot-embedding`, 1,024차원).
- BE 역할 `all`, 워커 동시 실행 4, 대기 제한 10분, 실행 제한 180초. FAQ 캐시 ON, 기본 유사도·점수 차이·가드 기준 유지. 실제 모델·검색·가드를 모의 처리하지 않았다.
- k6·BE·DB·Redis·모델이 같은 로컬 머신에서 실행됐다. 모델은 기동된 상태이고 질문 POST 전 health GET으로 연결을 준비했다. Nginx를 경유하지 않았다.
- 전용 DB의 합성 FAQ 3건과 그룹별 질문 1개씩을 반복한 통제 실험이다. 운영 데이터·다양한 질문·콜드 모델 성능으로 일반화할 수 없다. 회원 1,500명과 파일럿 10명은 전용 DB에 생성했다. 기존 개발 DB·운영 서버 설정·애플리케이션 소스는 변경하지 않았다.
