128개의 전체 완료 시간은 4개 대비 55.19%, 16개 대비 8.28%, 32개 대비 -3.09%, 64개 대비 -9.96% 감소했다. 음수 감소율은 시간이 늘었다는 뜻이다. 전체 시간은 각 POST 시작부터 DB `finished_at`까지로 인증·접수·워커 대기를 포함하며 폴링 지연·응답 전달·UI 렌더링을 제외한다. 대기 제외 처리는 `started_at → finished_at`으로 실제 임베딩·검색·가드·모델·저장을 포함한다. LLM p50/p95를 PostgreSQL `percentile_disc`로 교차 확인했다. 실패가 발생한 경우 LLM 시간 분포는 성공 건 기준이므로 오류·타임아웃 건수와 함께 해석한다.

- 판정: 4개 PASS / 16개 PASS / 32개 PASS / 64개 PASS / 128개 FAIL. 128개 요청 시작 범위 16ms, k6 종료 0.
- DB 실행 구간으로 계산한 최대 동시 작업은 128개다. 순간 지표의 최대 관측은 워커 128개·LLM 호출 128개이며 LLM 호출 상한 128개를 확인했다. 실제 생성 답변 표본 3건을 재조회했다.
- 임베딩 실패 1건(case 936, job/attempt 5061)은 API 코드 EM-003으로 분류됐다. 임베딩 지표상 실패 호출은 약 2.15ms, 작업 실행 전체는 약 14.20ms였고 설정된 임베딩 읽기 제한은 30초다. OpenAiCompatibleEmbeddingClient는 모든 ResourceAccessException을 EM-003으로 바꾸며 원인을 보존하지 않는다. 따라서 이 1건을 실제 30초 대기 초과로 확정할 수 없으며 네트워크 I/O 실패 가능성을 구분할 원인 로그도 없다. 표의 타임아웃 1건은 응답 코드 기준이고 실제 시간 초과 여부는 미확인이다. 오류 1건과 타임아웃 코드 1건은 같은 요청이다.
- GPU 관측: NVIDIA GeForce RTX 3060, 11244 MiB, 12288 MiB, 87 % (이름, 사용 메모리, 전체 메모리, 사용률). 128개 측정의 모델 서버 preemption 카운터 차이는 0이다.
- 각 설정을 한 번씩 측정했고 뒤의 실행은 전용 DB·모델 캐시를 재사용했다. 그룹별 같은 질문을 반복하며 k6·BE·DB·Redis·GPU는 같은 머신이다. 운영 성능 보장이나 최적 동시 실행 수의 통계적 증명으로 일반화할 수 없다.
