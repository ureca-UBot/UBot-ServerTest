# 실제 vLLM 워커 동시 실행 4 → 16 비교

2026-10-22 로컬 측정. 같은 회원 1,500명·질문·그룹 순서로 새 대화를 만들었다. 모델(Qwen3 4B, BGE-M3), GPU(RTX 3060 12 GiB), FAQ 3건, 캐시·임계값·DB 연결·힙·대기/실행 제한을 유지했다. 워커 동시 실행 환경변수만 4에서 16으로 바꿨다. 기존 기본값 연동에 따라 LLM 호출 상한도 4에서 16으로 변경됐다. 애플리케이션 소스와 .env는 수정하지 않았다.

| 시간 지표 | 워커 4개 | 워커 16개 | 감소율(음수는 증가) |
|---|---:|---:|---:|
| 전체 최종 처리 완료 | 273.09초 | 133.42초 | 51.1% |
| LLM 답변 전체 p50 | 137.81초 | 70.66초 | 48.7% |
| LLM 답변 전체 p95 | 258.73초 | 128.53초 | 50.3% |
| LLM 답변 전체 최대 | 273.08초 | 133.39초 | 51.1% |
| LLM 워커 대기 p95 | 254.20초 | 121.96초 | 52.0% |
| LLM 대기 제외 처리 p95 | 1.94초 | 3.79초 | -95.1% |
| 캐시 답변 전체 p95 | 263.32초 | 125.77초 | 52.2% |
| 캐시 대기 제외 처리 p95 | 0.05초 | 0.07초 | -22.6% |

전체 시간은 질문 POST 시작부터 서버 DB의 `finished_at`까지다. 인증·접수·워커 대기를 포함하며 폴링 지연·응답 전달·브라우저 렌더링을 제외한다. 처리 시간은 `started_at → finished_at`으로 임베딩·검색·가드·모델·저장을 포함한다. PostgreSQL `percentile_disc`로 LLM p50/p95를 교차 확인했다.

|---|---:|---:|

- 판정: 기존 **PASS**, 16개 **PASS**. 16개 요청 시작 범위 31ms. k6 종료 0, 중복 0건, 잘못된 이벤트 0건. 예상 밖 결과 {}.
- 실제 실행 중 관측: 워커 16개, LLM 호출 14개, LLM 호출 상한 16개. 모델 지표의 `kind=answer`에는 기존 스케줄러의 부가 호출도 포함된다. 채팅 성공 건수는 작업별 실제 처리 출처와 최종 상태로 판정했다.
- 합성 FAQ 3건·그룹별 동일 질문 반복, 같은 머신의 k6·BE·DB·Redis·GPU를 사용한 단회 비교다. 모델은 이미 기동됐고 연결도 사전 준비했다. 두 번째 실행은 기존 전용 DB·모델 캐시를 재사용했다. 감소율을 운영 환경의 보장값이나 통계적으로 검증된 최적 동시 실행 수로 해석하지 않는다.
